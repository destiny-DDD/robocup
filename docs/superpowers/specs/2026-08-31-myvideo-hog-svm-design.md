# myvideo A/B/C/D HOG+SVM 识别设计

日期：2026-08-31
状态：已确认设计，待实现

## 一句话

在 `myvideo` 新增串口模式 4：先从绿色背景中定位白色物块，再从物块中提取黑色字母，使用纯 OpenCV 的 HOG+SVM 识别 A/B/C/D，并把稳定结果显示在视频左上角。

## 背景与约束

- 当前节点已从摄像头读取画面，`run1`、`run2`、`run3` 分别实现颜色、模板和 Tesseract 识别；串口 `VideoMsg.num` 现在只接受模式 1 到 3。
- 目标为四个类别：A、B、C、D。
- 画面背景为绿色；目标字母仅出现在白色物块上，且字母为黑色。
- 字母位置不固定；通常一帧中只有一个字母，但实现必须能安全处理零个或多个白色物块。
- 当前仅有 A、B、C、D 四张模板图片，不能作为可靠训练集。
- 训练和运行时均只使用 OpenCV；使用 `cv::HOGDescriptor` 和 `cv::ml::SVM`，不引入 PyTorch、ONNX 或其他深度学习运行时。

## 方案选择

采用“白色物块定位 -> 黑色字母分割 -> HOG+SVM 分类”的两阶段方案。

直接在全图寻找黑色字符会把绿色背景阴影和其他物体纳入候选。利用白色物块与绿色背景的稳定视觉约束，可以先将分类范围缩小到白块内部，降低误检。HOG+SVM 对少量类别、轮廓清晰的字符足够轻量，并支持使用 OpenCV 直接训练、保存、加载和部署。

不采用整图分类：字母位置变化会破坏模型输入的一致性。

不采用滑动窗口：当前场景已有白色物块这一定位线索，滑动窗口的额外 CPU 开销没有收益。

## 数据与训练

新增训练目录，训练样本按类别保存：

```
src/myvideo/training/dataset/
  A/
  B/
  C/
  D/
```

每个样本是一张已裁剪的白底黑字图片。训练工具还应允许使用原始相机图时复用与 `run4` 相同的白块和黑字提取逻辑，避免训练与部署预处理不一致。

采集每个类别至少几十张、推荐数百张样本，覆盖：距离、轻微旋转/透视、不同光照、物块大小和背景中的绿色亮度变化。训练时必须按类别保留验证样本，输出每类正确率和混淆矩阵；验证不合格时先扩充数据，不靠降低阈值掩盖问题。

预处理和特征接口固定如下，训练工具和运行代码必须一致：

1. 黑色字符掩码经过最大有效轮廓筛选。
2. 字符置于留有固定边距的方形画布，保持纵横比。
3. 输出单通道二值 `64x64` 图，黑字作为白色前景。
4. 用固定 `cv::HOGDescriptor` 参数提取特征。
5. 以类别标签 `0=A`、`1=B`、`2=C`、`3=D` 训练多类 `cv::ml::SVM`。

训练完成后输出模型 `abcd_hog_svm.yml`，安装到：

```
share/myvideo/model/abcd_hog_svm.yml
```

## 运行时架构

### 初始化

`MyVideo` 首次进入 `run4` 时加载 SVM 模型。模型路径是 ROS 参数，默认值为包 share 目录的 `model/abcd_hog_svm.yml`。加载成功后缓存 `cv::Ptr<cv::ml::SVM>`；加载失败仅记录错误并在画面显示错误状态，不退出节点。

### 白色物块定位

每帧 BGR 图转换到 HSV，并用可配置的“低饱和度、高亮度”范围创建白色掩码。闭运算用于填补白色物块的小孔洞，再通过轮廓过滤去掉明显噪声：

- 最小面积；
- 合理的宽高比；
- 轮廓面积相对外接矩形面积的填充率；
- 可选的矩形程度。

每个保留的白块都会画出候选框，供现场调参和故障排查。所有 HSV 阈值和几何过滤阈值通过 ROS 参数提供，以适应相机曝光与现场光照。

### 黑色字符提取与分类

对每个白块 ROI 灰度化，再以可配置的黑色阈值进行反色二值化，令黑字成为白色前景。形态学操作清除小噪声后，选择面积最大且满足几何条件的字符轮廓。没有有效字符时跳过该白块。

有效字符轮廓按训练时定义的方形填充和 `64x64` 缩放规则归一化，随后提取 HOG 特征并调用 SVM 预测。OpenCV 多类 SVM 的 raw 输出不作为跨候选的置信度。在多个有效候选时，先按白块面积降序、字符相对面积降序、左上坐标升序进行确定性排序，再分类排序首项；保证结果确定且不依赖不可靠的模型分数。

### 结果稳定与显示

单帧预测不直接覆盖用户看到的结果。相同预测连续 3 帧后才成为已确认结果；中间无候选或类别改变会重置候选计数。左上角显示：

- 正常：`LETTER: A` 到 `LETTER: D`；
- 没有可用候选：`LETTER: ?`；
- 模型加载失败：`SVM unavailable`。

已选择的白块及字符轮廓以框线标注。显示继续使用现有 `show_window` 和 `ShowWindow`，无 `DISPLAY` 时不调用 `imshow`。

## 错误处理

| 场景 | 行为 |
|---|---|
| 摄像头读帧失败 | `run4` 返回 `false`，沿用主循环现有行为。 |
| 模型文件不存在、不可读或格式错误 | ROS error 日志一次，显示 `SVM unavailable`，节点持续运行。 |
| 无白色候选或无黑色字符 | 显示 `LETTER: ?`，不调用预测。 |
| 多个白块/字符候选 | 按白块面积、字符相对面积和位置确定性排序，分类排序首项；不假设只有一个。 |
| 串口收到 4 | 进入 `run4`。 |
| 串口收到不在 1 到 4 的值 | 沿用现有警告和忽略行为。 |

## 验证计划

1. 构建 `myvideo`，确认 OpenCV ML 和训练工具均可编译。
2. 用每类留出的验证样本训练并打印准确率、混淆矩阵；确认模型可保存和重新加载。
3. 无模型启动模式 4，确认窗口显示 `SVM unavailable`、ROS 节点不退出。
4. 绿色背景且无白块，确认显示 `LETTER: ?`，不崩溃。
5. 绿色背景、白色物块、黑色 A/B/C/D 各自测试，确认左上角在连续三帧后显示正确类别。
6. 在不同位置、距离和光照下重复第 5 步；记录误识别样本并补充训练集。
7. 加入多个白块或白块内没有黑字，确认选择行为确定、无越界或崩溃。
8. 发送串口模式 4，确认主循环执行 `run4`；模式 1 到 3 的原有行为不变。

## 范围外

- 不使用 CNN、深度学习框架或 ONNX。
- 不做任意场景中的文本检测，也不识别 A/B/C/D 之外的类别。
- 不改变模式 1 到 3 的检测算法和串口协议结构。
